## Where the router fails, and why the planner doesn't
- Repetition ("three times", "twice"): the router has no count, so 4 of 4 fail. Gemma sets `repeat`.
- "and" joins ("sit down and say hello"): the splitter only splits on "then", so it drops the
  second action in 3 of 3. Gemma splits by meaning.
- Mislabels inside a clause: "stand still" → sit_or_stand, "gently coo" → unsupported,
  "say hello then fly away" → one `unsupported` for both. With a whole-request view and a
  constrained output, Gemma made none of these.

## Caveats, recorded
- **Ceiling.** 30/30 means this set is too easy for the planner to rank variants. The next set
  (p003) needs harder requests: nested counts ("twice, then three times"), negation ("don't
  sit"), references ("do that again"), long plans (8+ steps), and grounded targets ("walk to the
  ball"), which step 4 adds.
- **Latency is the real cost.** At 28 s median on CPU, this is not an interactive loop. The
  options are GPU offload (this llama.cpp build is CPU-only), E2B (about half the size), prompt
  caching (the system prompt is the same each time), or an on-device Apple/MLX model on the
  phone. The router stays useful as the instant first guess while the planner thinks.
- One model and one seed, at temperature 0.
