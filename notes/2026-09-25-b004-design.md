# b004 design: one student, seven skills, smooth switches

Pre-registered 2026-09-25, before any b004 training ran.

## Question
Pollen ships one network per skill (velstand, stand, sitstand, ground_pick, ball_kick_left/right).
A sequence such as "walk, sit, get up, peck" swaps networks at every step. Swapping lands each new
network in a state its own training never saw, which can make the duck fall. Can one small student,
given a 3-slot skill code in the command block (obs 55, 56, 60), reproduce every teacher *and*
switch between skills without falling more often than network swapping does?

## Setup
- Teachers: the six Pollen ONNX files, fetched by pinned revision and sha256 (`scripts/fetch_teachers.sh`).
- Skills: walk, stand, sit, unsit, pick, kick_left, kick_right (`src/duckbatch/skills.py` SKILLS).
- Each env draws a skill schedule, and the active teacher labels its frames (population DAgger).
  Switching happens during training, so the student sees the post-switch states that the teachers never trained on.
- Walk profile throughout: no prone spawns, because the sit and pick teachers never learned to get up.
- Arms: 512-256-128, 256-128-64 and 128-128, trained side by side in one 512-env batch.

## Measures (held-out seeds 6001–6003, 30 s, the same schedule for every arm)
- falls per 100 switches, counted in the 2 s window after each switch;
- mean action gap to the active teacher, by skill;
- the reference arm: the teachers themselves, swapped at every switch (network swapping).

## Pass lines
1. At least one arm has falls per 100 switches ≤ the swapping baseline's.
2. That arm's gap on walk is ≤ 1.5× b002's a02 walk gap.
3. No skill's gap exceeds 3× its walk gap (no skill silently dropped).

Failing 1 while passing 2–3 is still a result: it means the one-network approach costs switch
safety, and the transition problem needs its own data (for example, a switch-time curriculum).
